# Android/Termux CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run dotfiles bootstrap, doctor, and tests inside the official Termux application on Android and require that check before merge.

**Architecture:** Keep the existing eight-platform shell matrix intact and add a sibling caller job for the already pinned `termux-ci.yml` reusable workflow. The caller supplies only the Termux-side bootstrap and test command; the shared actions repository continues to own emulator and sandbox mechanics.

**Tech Stack:** GitHub Actions reusable workflows, Bash, Termux `pkg`, dotfiles `dot` and `dot-test`

## Global Constraints

- Do not modify `cgraf78/actions` or add Android to the shared `full` matrix.
- Pin the public Termux reusable workflow to `feeba8dcb271bd206ae55cd735e53577ffa08877`.
- Forward no repository secrets into the Termux sandbox.
- Install only `git` and `curl` before exercising the normal dotfiles bootstrap.
- Land only after the selector, eight shell platforms, and Android/Termux are green and required.

### Task 1: Add the Android workflow contract and caller

**Files:**

- Modify: `.local/lib/dot/tests/core/static.sh`

- Modify: `.github/workflows/test.yml`

**Interfaces:**

- Consumes: the public `termux-ci.yml` input `command`, executed from the copied checkout inside the official Termux sandbox

- Produces: a `termux` caller job guarded by the core static suite

- [ ] **Step 1: Write the failing workflow-contract assertion**

Extend the existing workflow scanner with `_ci_in_termux_job=0` and
`_ci_has_termux_pin=0`. When the two-space job key is parsed, set
`_ci_in_termux_job=1` only for the `termux` key and reset it for every other
job. Set `_ci_has_termux_pin=1` only when that job contains:

```text
uses: cgraf78/actions/.github/workflows/termux-ci.yml@<40 lowercase hex characters>
```

After the scan, report:

```bash
if ((_ci_has_termux_pin)); then
  _pass "CI workflow: runs Android tests through pinned Termux workflow"
else
  _fail "CI workflow: runs Android tests through pinned Termux workflow"
fi
```

The production break this catches is deleting, commenting out, moving, or
unpinning the Android caller job.

- [ ] **Step 2: Run the focused test and verify RED**

Run:

```bash
.local/bin/dot-test core
```

Expected: FAIL with
`CI workflow: runs Android tests through pinned Termux workflow`, because the
workflow has no `termux` job yet.

- [ ] **Step 3: Add the minimal Termux caller**

Add this sibling of `jobs.shell`:

```yaml
  termux:
    uses: cgraf78/actions/.github/workflows/termux-ci.yml@feeba8dcb271bd206ae55cd735e53577ffa08877
    with:
      command: |
        pkg install -y git curl
        export CI=1 GITHUB_ACTIONS=1
        export HOME=$PWD
        export PATH="$HOME/.local/bin:$PATH"
        .local/bin/dot update --skip-pull
        .local/bin/dot doctor
        .local/bin/dot-test
```

- [ ] **Step 4: Run focused validation and verify GREEN**

Run:

```bash
.local/bin/dot-test core
actionlint .github/workflows/test.yml
```

Expected: both commands exit zero and the core suite reports
`CI workflow: runs Android tests through pinned Termux workflow` as passing.

- [ ] **Step 5: Run full local verification**

Run:

```bash

git diff --check origin/main..HEAD
```

Expected: all commands exit zero.

Commit the workflow, static test, design, and plan using the repository commit
